How it works

One rule: it has to happen twice.

A bug report you cannot trust costs more time than the bug. So Owly proves everything it says before it says it.

One run

Four phases, ninety seconds.

PHASE 1

Discover

Opens your site as a new desktop visitor, follows the most prominent call to action, and checks every page it reaches.

PHASE 2

Personas

The same pages twice more: as an impatient phone user at 390px, and as someone with only a keyboard.

PHASE 3

Verify

Every suspected problem is replayed in a fresh browser. No repeat, no report: it is listed as unverified instead.

PHASE 4

Write it up

Duplicates clustered, secrets redacted, and a page that opens with the answer and backs it with screenshots.

Verification

Proving the site is yours.

Any site can be looked at. To let Owly type into forms and press buttons, publish a token it derives from your hostname. Any one of these works:

/.well-known/owly-verification.txt      contains the token

<meta name="owly-verification" content="owly-...">    in your head

DNS TXT   owly-verification=owly-...

Ask Owly for your token on Pond. Until it is there, a test is a passive scan: it looks at pages, layout and accessibility, and presses nothing.

Where the model is, and where it is not

Owly can hold a conversation, and that part is a language model. It is kept strictly outside the testing: it can explain a report in plainer words, and it can ask for a test to be started — but it cannot start one itself, and it is never the source of a finding. Every issue in a report is something a real browser did and recorded, twice. Ask Owly about a site it has not tested and it will tell you it has not tested it, rather than guessing.

What it cannot find

Anything that needs judgement: a confusing label, an unhelpful error message, a total that is wrong but renders perfectly. Owly says so rather than guessing — its own benchmark counts those as misses.

How good is it, actually

Owly is scored against a lab of deliberately broken apps plus one control app with nothing wrong at all. Current score: 23 of 26 planted defects found — every one that can be found without judgement — at 100% precision, zero false positives on the control app, zero safety-rule violations. The build fails if any of those slip. The three it misses are listed in the open, not hidden: all three need a judgement call a model would have to make.

And when it cannot reach you

A run where no page opened says exactly that. It is never presented as a clean bill of health, and it is not counted against your free tests.
